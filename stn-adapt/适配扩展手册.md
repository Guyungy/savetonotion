# 给新网站做保存适配 —— 操作手册

> 前置结论：**这个扩展没有配置化的适配机制。** 所有网站适配都硬编码在压缩产物
> `serviceWorker.js` 和 `content/content.js` 里，且 `manifest.json` 的
> `content_scripts` 为 `null`（全部走 `chrome.scripting.executeScript` 按需注入）。
> 因此「加适配」只有两条路：**改源码重打包** 或 **运行时打补丁**。

---

## 一、先搞清楚：四层适配，各改哪里

| 层 | 目标 | 位置 | 难度 |
|---|---|---|---|
| ① 元数据覆写 | 改 title / icon | `serviceWorker.js` 的 `oa`（pos 4797） | 极低 |
| ② URL 参数清洗 | 删追踪参数 / 保留 hash | `serviceWorker.js` 的 `ec`/`tc`/`nc`/`ac`（pos ~72083） | 极低 |
| ③ 页面结构解析 | 抓正文/作者/图片存成列表 | `content/content.js` 的 `Zn` + `Jn`（pos 84131） | 中 |
| ④ 上下文按钮注入 | 在页面上插「Save.to」按钮 | 同 ③ 的 `contextualButton` 段 | 中 |

绝大部分需求只需要 ① 和 ② —— **这两层是纯数据表，加 key 即可，零逻辑**。

---

## 二、路径 A（推荐）：只改 ①②，改数据表

这两层是纯字典，不涉及 DOM 遍历逻辑，风险最低。

### A1. 加元数据覆写

在 `serviceWorker.js` 搜 `"mail.google.com":{icon:`，找到 `oa` 表，按同样格式加条目：

```js
const oa = {
  "mail.google.com": { icon: "https://.../Gmail_icon.svg" },
  "youtube.com": { title: (data, tab) => ..., icon: "https://.../YouTube.svg" },
  "x.com": { title: (data, tab) => ... },

  // ▼ 新增站点示例
  "medium.com": {
    // data  = parseMetaTags.js 抓到的字段（含 yt_author / x_article 等自定义字段）
    // tab   = chrome.tabs 的 tab 对象（tab.title / tab.url）
    title: (data, tab) => data.title.replace(/\s*[|–-]\s*Medium\s*$/, "").trim(),
    icon: "https://medium.com/favicon.ico",
  },
};
```

**三个硬性注意点：**

1. **key 必须去掉 `www.`**。`oa` 的查表代码是
   `hostname.replace(/^www\./,"")`，所以写 `youtube.com` 而不是 `www.youtube.com`。
   ⚠️ **但 ② 层的 `nc` 表用的是带 www 的 key** —— 两张表规范不一致，别搞混。
2. `title` 可以是**函数 `(data, tab) => string`** 或**字符串**。函数返回值直接用。
3. `data` 里可用的自定义字段，取决于 `parseMetaTags.js` 抓了什么（通用 og/meta
   字段 + YouTube 的 `yt_author`/`yt_title` + X 的 `x_article`）。想加自定义字段，
   得同时改 ③ 的 `parseMetaTags.js`。

### A2. 加 URL 清洗规则

同文件搜 `"www.reddit.com":{ref:!0}`，找到 `nc` 表：

```js
const ec = { fbclid:!0, gclid:!0, /* 全局删，15 个 */ },
      tc = /^utm_/,
      nc = {
        "www.youtube.com":  { ab_channel: !0 },
        "www.x.com":        { ref_src:!0, ref_url:!0, s:!0, source:!0 },
        "www.linkedin.com": { trk: !0 },
        "www.reddit.com":   { ref: !0 },

        // ▼ 新增：按域名删参数（key 要带 www，如果站点确实用 www）
        "www.bilibili.com": { spm_id_from: !0, vd_source: !0, from_source: !0 },
      },
      ac = { "mail.google.com": !0 };   // ac = 保留 hash 锚点的白名单
```

- 加站点专属参数 → 进 `nc`
- 加全局脏参数 → 进 `ec`
- **要保留 hash（如 Gmail 的 `#inbox/xxx`）→ 加进 `ac`**，否则 hash 会被清空

> 找不到完整路径时直接搜特征串：`"www.reddit.com":{ref:!0}`、`ab_channel`、`fbclid`。

## 三、路径 B：改 ③④，加 parser（工作量大）

适用场景：要让新网站在页面上**出现「Save.to」悬浮按钮**，或**把列表页/详情页抓成结构化条目**。

注册表在 `content/content.js` pos 84131：

```js
const Zn = {"www.linkedin.com": "linkedin"},        // hostname → 站点标识（注意带 www！）
      Jn = { linkedin: { resources: [ /* ... */ ] } };  // 站点标识 → 资源定义
```

要加站点，就是往 `Zn` 加映射、往 `Jn` 加定义。

### parser schema（引擎在 pos 28253–36000）

**一个资源 = `{ type, parser: [ ... ] }`**，`type` 是 Notion 数据库的类型名
（已见到：`people` / `post` / `mail` / `webpage` / `photo` / `video` / `article`）。

```js
{
  type: "people",
  parser: [
    {
      description: "my site person page",   // 仅调试用
      mode: "unique",                        // unique = 整页一条；list = 多条
      mainContainer: [                       // 或 itemContainer（list 模式必填）
        { selector: "#profile-content" },
        { selector: "main" },                // 数组 = 逐级收窄，任一命中即可
      ],
      attributes: [
        { name: "url", valueExtractor: { currentUrl: true },
          transform: { fn: ["ignoreQueryParams", "addTrailingSlash"] } },

        { name: "webpageTitle",
          altNames: ["name", "title", "resourceTitle"],   // 别名，同一值多个 key
          valueContainer: { selector: 'a[href*="about"] h1' },
          valueExtractor: { text: { type: "textContent" } } },

        { name: "location",
          valueContainer: { leftOfContainer: {
            selector: 'a[href*="/contact"]', parentDepthLimit: 3,
            parentContainer: { selector: "span" } } },
          valueExtractor: { text: { type: "first_match", minLength: 2 } } },
      ],
      contextualButton: {                    // 有这段才会注入按钮
        htmlRender: '<button aria-label="Save.to" class="...">Save to</button>',
        injectContainer: { leftOfContainer: {
          selector: 'button[aria-label="More actions"]',
          parentDepthLimit: 2, parentContainer: { selector: "div" } } },
      },
    },
    {
      mode: "list",                          // 列表模式
      itemContainer: { selector: 'div[data-urn*="activity"]' },   // 可选数组做链式收窄
      attributes: [ /* 同上层 */ ],
    },
  ],
}
```

### `valueContainer` 定位原语（可组合）

| 原语 | 含义 |
|---|---|
| `{ selector: "css" }` | 直接 CSS 选择器 |
| `{ classIncludes: "foo" }` | 等价 `[class*="foo"]` |
| `{ mainContainer: [...] }` | 整页容器（unique 模式） |
| `{ itemContainer: [...] }` | 列表项容器（list 模式） |
| `{ leftOfContainer: {...} }` | 取目标**左侧**元素 |
| `{ rightOfContainer: {...} }` | 取目标**右侧**元素 |
| `{ parentContainer: {selector}, parentDepthLimit: 3 }` | 向上找 N 层父级 |
| `{ rightSibling: true }` | 取右兄弟 |
| `{ or: [ {...}, {...} ] }` | 任一命中 |
| **数组 `[a, b, c]`** | 逐级收窄链（在 a 结果里找 b，再找 c） |
| `{ selector: "img", index: 0 }` | 第 N 个匹配 |

### `valueExtractor` 取值方式

```js
{ text:  { type: "textContent" } }                        // 全文
{ text:  { type: "first_match", minLength: 2 } }          // 首个够长的文本节点
{ attribute: "src" }                                      // 取属性
{ html:  { type: "innerHTML", cleaned: true } }           // 取 HTML（正文用）
{ currentUrl: true }                                      // 当前页 URL
```

### `transform` 变换

```js
{ fn: "addTrailingSlash" }              // 内置字符串名
{ fn: "ignoreQueryParams" }
{ fn: "extractFirstName" }
{ fn: ["ignoreQueryParams", "addTrailingSlash"] }   // 链式
{ regex: "•\\s*([^•]+)$" }              // 正则捕获组
{ fn: (v) => `https://.../update/${v}/` }           // 自定义函数
```

### `urlFilter` 门禁（在 `parser` 层，不在 attributes 里）

```js
{ urlFilter: { match: [/\/profile\//], notMatch: [/\/edit/] } }
```

## 四、路径 C（不改打包产物）：运行时打补丁 ⭐

**这是给「不确定要不要永久改」的场景最实用的路子。** 原理：

1. `manifest.json` 的 `content_scripts` 是 `null`，但扩展有 `scripting` 权限，
   自己的代码是用 `chrome.scripting.executeScript` 注入的。
2. 注入的脚本是**独立 content script world**，模块作用域隔离 ——
   **外部拿不到 `Jn` / `Zn` 的引用**，所以不能直接改表。
3. **但 `window.__stnModule` 是挂在 window 上的**（pos 64669），且 `$i`/`Di`
   导出表是普通对象。可以利用这点做**包装式拦截**。

### 补丁模板（新增 `stn-adapt/adaptive.js`，在 popup 打开前注入）

```js
// stn-adapt/adaptive.js —— 运行时适配补丁
(function () {
  "use strict";
  var G = (typeof window !== "undefined") ? window : globalThis;

  // 站点适配表：hostname → 覆写规则（无需改 serviceWorker.js）
  var SITE_RULES = {
    "medium.com": {
      cleanParams: ["source", "gi"],                       // 追加要删的参数
      titleSuffix: /\s*[|–-]\s*Medium\s*$/i,               // title 要去掉的后缀
    },
    // 「示例站点」...
  };

  function hostKey() {
    return location.hostname.replace(/^www\./, "");
  }

  // ---- 1) 拦截保存前的 URL 正规化（对 cleanupUrl 做后置补刀）----
  // 把结果 URL 里的自定义参数再删一遍
  G.__STN_ADAPT__ = {
    rules: SITE_RULES,
    cleanUrl: function (url) {
      var r = SITE_RULES[hostKey()];
      if (!r || !r.cleanParams) return url;
      try {
        var u = new URL(url);
        r.cleanParams.forEach(function (p) { u.searchParams.delete(p); });
        return u.href;
      } catch (e) { return url; }
    },
    cleanTitle: function (title) {
      var r = SITE_RULES[hostKey()];
      if (!r || !r.titleSuffix) return title;
      return title.replace(r.titleSuffix, "").trim();
    },
  };
})();
```

**注意：** 这条路径只能做「后置补刀」（拿到 URL/title 后再改），
**无法新增 parser**（拿不到 `Jn`）。要加 parser 必须走路径 B。

## 六、坑清单（务必先读）

1. **🔴 目录名禁止 `_` 开头。** Chrome 保留 `_locales`/`_metadata`，
   会导致**扩展加载直接失败**（已踩过，`_i18n` → `stn-i18n`）。
2. **`oa` 表 key 去 www，`nc` 表 key 带 www。** 同一个文件两套规范。
3. **`gmailIntegration.js` 是空壳。** 166KB 里主体是 gmail.js v0.8.0 第三方库，
   `loadInboxSDK()` 整段被注释、`main()` 只打 `console.log("hello world")`。
   想真正做 Gmail 适配得自己接线，别以为改几行就好。
4. **改压缩产物会丢改动。** 扩展升级覆盖文件后，所有手改都会没。
   → 优先路径 C（独立文件），或维护一个「改动清单」用于重放。
5. **不要改 `manifest.json` 的 `content_scripts` 为数组来加脚本。**
   扩展的注入体系依赖 `scripting.executeScript`，混用两套注入会导致
   执行顺序和 world 隔离出问题。
6. **`Chrome 的 CSP 是 `script-src 'self'`**，不能用远程词典/远程配置，
   所有适配数据必须落成扩展自身文件。

## 七、决策建议

| 你的需求 | 走哪条路 |
|---|---|
| 只是 title/icon 不对、URL 有脏参数 | **A**（改两张数据表，10 分钟） |
| 想让某站点支持「一键保存列表」 | **B**（写 parser，按 schema 填，1–2 小时/站） |
| 想先试试、不想动打包产物 | **C**（独立补丁文件） |
| 想批量适配 10+ 站点 | **A + C 组合**：A 处理能静态搞定的，C 兜剩下的 |

**最后一条现实提醒：** 路径 B 每加一个站点，都要跟着目标站点的 DOM 结构走。
站点改版 = 你的 parser 失效。这不是一劳永逸的活，建议只给**高频且结构稳定**
的站点做 B，其余用 A/C 兜底。

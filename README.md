# Save.to：保存到 Notion / 飞书，中文界面与网站适配

基于 Save.to（原 Save to Notion）v4.3.14 解包扩展进行维护，提供中文界面和网站抓取适配。支持把网页正文或选取的页面区域保存到 Notion，也可选择启用飞书同步钩子，在 Notion 保存成功后将同一份内容同步为飞书云文档。本仓库为本地修改版，Notion 使用原产品的账号与连接流程，飞书独立配置 App ID / App Secret。

## 安装与更新

1. 下载本仓库 ZIP 并解压，或克隆仓库：

   ```sh
   git clone https://github.com/Guyungy/savetonotion.git
   ```

2. 在 Chrome 打开 `chrome://extensions`，启用开发者模式。
3. 点击「加载已解压的扩展程序」，选择包含 `manifest.json` 的仓库根目录。
4. 保存到 Notion 时，按照扩展界面提示完成账号连接；如需同步到飞书，参考下方「飞书可选同步钩子」，在原保存面板启用并配置。

更新本地代码后，在扩展管理页面点击重新加载，再刷新要保存的网页。已安装商店版时，使用扩展名称和 ID 核对当前加载版本，避免混用。

## Linux.do：楼层和评论保存

支持 `https://linux.do/t/<slug>/<topic-id>` 话题页及末尾带楼层编号的链接，例如 `/t/topic/1675456/57`。需要在浏览器中能正常查看目标内容。

| 保存方式 | 保存范围 |
| --- | --- |
| 整页正文保存 | 保存瞬间页面已加载的楼层，以及已展开的评论 |
| 选取页面区域 | 所选单楼、多楼容器或展开评论区内的内容 |
| 选取一段文字或一张图片 | 仅所选内容，不自动扩大为整层 |
| 列表选取 | 所选条目的正文及楼层上下文 |

每条楼层或评论带有楼层号、作者、原帖链接，以及页面可提供的发布时间。保留正文标题、引用、链接卡片和表情；灯箱图片使用原图地址。头像、操作按钮、站点小图标和图片尺寸提示会被移除。折叠说明块展开为带引用标题的正文；代码保留原始反引号、缩进和换行，图片不再嵌套灯箱链接。同一条回复同时出现在展开区和普通楼层时会去重。

**保存单独某楼**：先跳到目标楼层，再用扩展的页面区域选择功能选中该楼。选择整楼时，也会包含该楼内已展开的评论。楼层链接的元数据会保留对应作者、时间和楼层编号。

**保存一段讨论**：先滚动到需要的范围，让楼层正文加载出来；需要展开回复时先在网页中展开，再选择包含这些楼层或评论的区域保存。

Linux.do 使用动态加载：滚动时会加载新楼层，也可能卸载较早的楼层。因此“当前页面”包含实际留在 DOM 中的正文，可能包括屏幕之外的相邻楼层，**不代表整个话题**。默认不会自动遍历所有楼层、展开折叠评论或获取无权访问的内容。

实现与开发接口见 [Linux.do 适配说明](stn-adapt/linuxdo适配说明.md)。

## 维护注意事项

- 扩展目录内的文件或目录不要以 `_` 开头：Chrome 将此前缀保留给系统，可能拒绝加载整个扩展。临时文件使用 `tmp-`、`test-` 或 `verify-` 前缀。
- 上游扩展升级可能覆盖本地修改；升级后需重新检查并应用适配补丁。
- `getLinuxDoArticle` 分别存在于三个独立注入脚本中。修改时保持一致，回归测试会检查一致性。
- 提交页面快照时仅保留测试所需内容，移除登录令牌及其他会话数据。


## 飞书可选同步钩子

飞书是 **Notion 保存成功后的可选同步钩子**，默认关闭。继续使用原来的 Notion 保存入口和目标配置；原保存表单在“更多字段”（如 `3 more fields`）这一行的右侧提供原生 **同步到飞书** 复选框和设置齿轮。控件直接由表单 React 组件渲染，不依赖外部脚本查找或插入 DOM。不再提供独立的飞书右键菜单、保存按钮或第二套正文提取流程。

1. 点击“设置”，填写飞书企业自建应用的 **App ID / App Secret** 以及可选的云空间文件夹链接（`/drive/folder/…`）或 token。
2. 在[飞书开放平台](https://open.feishu.cn/app)启用应用机器人能力，开通云文档创建、编辑和“文本内容转换为云文档块”权限，并发布应用版本。相关接口：[文档创建](https://open.feishu.cn/document/server-docs/docs/docs/docx-v1/document/create)、[内容转换](https://open.feishu.cn/document/ukTMukTMukTM/uUDN04SN0QjL1QDN/document-docx/docx-v1/document/convert)、[嵌套块写入](https://open.feishu.cn/api-explorer?project=docx&resource=document.block.descendant&apiName=create&version=v1)。新增权限后重新发布并获得管理员批准（如需要）。
3. 建议指定应用和你的账号都有编辑权限的目标文件夹。未填文件夹时，文档归应用所有。保存后默认自动设置为 **应用所属企业内获得链接的人可编辑**，并关闭对外分享，无需逐篇向应用申请访问权限。
4. 验证并保存设置，然后勾选 **同步到飞书**。也可以在设置页勾选“启用：Notion 保存成功后同步到飞书”。取消勾选立即关闭后续保存的同步，无需删除凭证。旧版本已保存的凭证会保留，但不会自动启用。
5. 按原流程点击“保存到 Notion”。写入成功后，后台同步飞书，面板显示同步结果及文档链接；关闭面板后也可在下次打开时查看最近一次结果。

**内容与范围：** 钩子直接读取本次 Notion 提交的标题与正文，不重新抓取网页。整页、选取的页面区域和列表条目沿用 Notion 本次保存范围；Linux.do 不扩大为整个主题，不加载额外楼层。你编辑的标题会保留。未提交正文时，只同步标题/笔记和已有原文链接。普通页、数据库条目及立即保存的笔记使用同一成功入口；高亮、截图和尚未实际写入的排队任务不触发此钩子。

**已有文档权限修复：** 更新并重新加载扩展后，进入飞书“设置”，点击 **设置企业内可编辑**。文档链接留空时修复最近一次保存的文档，也可填写本应用创建的 `/docx/…` 链接。只修改该文档的分享设置，不重新保存正文。组织分享策略仍可能限制设置；权限接口失败时保留文档链接，并明确显示“企业内编辑权限设置失败”。

企业内范围以应用所属企业为准，登录其他企业的账号不属于这一范围。个人收藏更适合通过飞书用户 OAuth 授权，以 `user_access_token` 创建文档，文档直接归本人所有；需要一次登录授权和令牌续期。本版继续使用 App ID / App Secret 的应用身份方案。

**格式：** 已提交的 Markdown 通过飞书转换接口写入，支持标题、段落、列表、链接、引用、代码块和表格，最终样式由飞书决定。图片目前转换为原图链接，不上传图片；视频、原站 CSS 和交互组件不会完整保留。正文附此次保存已有的原文链接。

**结果与失败：** 只有 Notion 写入成功后才同步。飞书在后台执行，失败不会改变 Notion 的成功状态，也不会重试 Notion。每次成功提交新建一篇飞书文档，不追加到已有文档。内容按父子结构分批写入，每批最多 1000 块；单个超限结构会在文档创建前报错。飞书正文部分写入时，保留已创建文档链接并提示失败。不会自动重试写入，以免重复段落。最近一次状态存于本地；关闭开关不会取消已经开始的同步。

**凭证：** App Secret 仅存 `chrome.storage.local`，不使用同步存储，不写入源码；该存储不加密，请在可信设备配置。清除应用设置会删除凭证与最近结果并关闭钩子。公开面板只可读取开关状态、查看同步结果、切换开关和打开私有设置页，不能读取凭证或单独提交飞书保存。凭证只发送到飞书官方认证接口，仓库不含默认凭证。
